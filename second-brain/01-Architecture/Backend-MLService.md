# Backend: ml-service

A Python package (`ml-service/`), not a single monolithic API — it's mostly a set of ordered CLI scripts plus a thin FastAPI feedback-loop service (`main.py`).

## Layout

- `data_pipeline/` — `preprocess.py` (entity resolution, crosswalk, barangay veto — [[../02-Decisions/D04-Barangay-Veto-Crosswalk]]) and `feature_engineering.py` (target variable construction, proxy dates, Phase 8 clamp, feature engineering, train/test split).
- `models/` — `train_trees.py` (Random Forest + XGBoost), `train_lstm.py` (LSTM), `train_meta_learner.py` (Level 1 stacking).
- `optimization_engine.py` — PuLP linear program for inspector scheduling.
- `inference/` — SHAP explanation module (`explain.py`), used both by batch scoring (`seed_supabase.py`) and live single-project rescoring.
- `artifacts/` — trained model files (`.joblib`, `.keras`), OOF predictions, metrics JSON. Not committed to git (regenerated by the pipeline).
- `main.py` — the FastAPI service, used for the live rescore path from the frontend.

## Why scripts, not a training service

Training happens offline, on a schedule the researcher controls (re-run after any pipeline/data change), not on every request. The FastAPI service exists only for lightweight, already-trained-model operations (rescoring one project's SHAP explanation on demand), not for training or batch scoring. See [[../03-ML-Pipeline/Stage7-Seed-Supabase]] for the actual batch-write path.

## Stack

pandas (pinned `<3.0` — see [[../06-Operations/Sandbox-Constraints]] and `requirements.txt`'s own comment for why), scikit-learn, XGBoost, TensorFlow/Keras (LSTM), SHAP, PuLP, FastAPI/uvicorn, Supabase Python client. Full pipeline detail: [[../MOC-ML-Pipeline]].
